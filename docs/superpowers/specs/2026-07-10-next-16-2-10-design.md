# Next.js 16.2.10 Patch Update Design

## Context

The maintenance backlog requires dependency changes to use focused owner-reviewed branches with full verification. The repository currently resolves `next`, `@next/bundle-analyzer`, `eslint-config-next`, and `@next/eslint-plugin-next` at 16.2.9; npm reports 16.2.10 as the compatible wanted release for all four.

The official Next.js 16.2.10 release states that it contains no code changes except publishing `@next/swc-wasm-web`, which had accidentally not been published since 16.2.4.

## Decision

Align only the four direct Next packages to `^16.2.10` in one dependency-family batch. Accept lockfile changes only for:

- the root ranges for those four packages;
- `next`, `@next/bundle-analyzer`, `eslint-config-next`, and `@next/eslint-plugin-next`;
- `@next/env`; and
- the existing platform-specific `@next/swc-*` optional packages.

Reject unrelated dependency or lockfile churn. Preserve dependency/devDependency placement, npm lockfile version, Node requirements, application code, data, schemas, and environment contracts.

## Validation

Run a clean `npm ci`, formatting, lint, type-check, the full Vitest suite, production build, high-severity audit, reference checks, root hygiene, and lockfile/package inspection. Confirm the build does not change tracked embeddings and obtain an independent dependency-diff review before delivery.

## Rollback

Revert the two dependency files and rerun `npm ci`. No migration, data rollback, deployment, or external-system action is required.
